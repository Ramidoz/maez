Maez is the brain. Surfaces are just doors.

The card-vs-run decision lives inside Maez, not inside Telegram. Fixing Telegram won't change this — flipping the default will.

What changes in the flip: one classifier rule inside the decision pipeline — the branch that decides "card or inline." Safety rails (audit, covenant, will-I check, fabrication detector) still run on BOTH paths. What's removed is the friction of asking permission for things the authenticated owner has already been granted. What stays is the refusal surface for the small set of acts that actually deserve a second look.

What doesn't change: the brain, the memory, the loops, the self-model, the residue system, the capability registry, the fabrication memory. Every surface already consumes the same prompt stack. Every surface already routes through the same decision pipeline. The fix is one decision rule, not a Telegram rewrite.
