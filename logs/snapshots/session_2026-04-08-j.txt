========================================
WHAT WENT WRONG / RIGHT:
========================================

WRONG — Ollama timeout during standalone test:
The trigger's generate_diff() calls Ollama, but the daemon holds the GPU. Standalone tests
can't get Ollama responses while the daemon is running with its own model loaded. This is
expected — the trigger is designed to run INSIDE the daemon process where Ollama access
is available. Created the validated candidate manually to prove the rest of the flow.

RIGHT — All 7 conditions evaluated and logged:
Every trigger evaluation logs exactly which condition passed or failed and why. No silent
suppression. The evolution.log has a complete audit trail.

RIGHT — Structural validator catches bad diffs:
The _validate_diff_structure function rejects any diff touching def, class, import, or
control flow lines. This is enforced in code, not just prompt wording. Combined with
MAX_PROPOSAL_HUNKS=1 and MAX_PROPOSAL_CHANGED_LINES=8, the attack surface is minimal.

RIGHT — the owner always decides:
AUTO_APPLY_ENABLED = False is hardcoded. The trigger creates validated candidates and
sends notifications. It never acquires the lock, patches files, or restarts the daemon.
The show/apply/reject CLI gives the owner full control.

RIGHT — Continuity integration:
set_mode_override('corrective') fires after a validated proposal, ensuring the next
capsule captures the mode change. Override is consumed after one write (transient).
