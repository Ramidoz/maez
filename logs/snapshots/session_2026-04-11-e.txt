========================================
THE TL;DR
========================================

1. NEW module `core/soul_editor.py` (~340 lines). Parses soul.md into
   a protected preamble (HARD CONSTRAINTS / TRUST COVENANT / SYSTEM
   BASELINE / identity — unreachable from the editor) plus a list of
   `## Header`-delimited editable sections. Builds section-replacement
   Proposals with unified diffs. Applies them via reparse + stale-
   check + required-phrase check + timestamped backup + atomic
   os.replace. Refuses any new body containing self-destruct phrases
   (`kill ollama`, `disable ollama`, `stop maez`, `override TRUST
   COVENANT`, etc.).

2. `core/dream_state.py` schema migration: `dream_proposals` table
   gained `proposal_type` (default 'append'), `target_section`,
   `proposed_new_body`, `unified_diff` columns. Added
   `store_section_edit_proposal`, extended `list_pending` with a
   proposal_type filter, extended `get_proposal` to surface the new
   columns, and added `apply_section_edit_proposal` which delegates
   to the ActionEngine.

3. `core/action_engine.py` new Tier 0 action: `edit_soul_section`.
   Goes through `_execute_action` for logging + trust tracking, then
   `_do_edit_soul_section` calls `soul_editor.propose_replacement`
   + `soul_editor.apply_section_replace`.

4. Four new private Telegram bot commands in `skills/telegram_voice.py`:
   `/edit_proposals`, `/show_edit <id>`, `/apply_edit <id>`,
   `/reject_edit <id>`. Parallel to the 11o `/dreams` family but for
   section-replace proposals. Registered in the bot command menu
   (now 19 commands, up from 15).

5. Found and fixed a correctness issue discovered during testing:
   `soul_editor.load()` had `def load(path: Path = SOUL_PATH)` which
   bound the default at def time, so monkey-patching
   `soul_editor.SOUL_PATH` for tests had no effect. Changed to
   `def load(path: Optional[Path] = None):` with lazy resolve.

========================================
WHAT THIS ENABLES
========================================

Before 11s: Maez could propose appending a dream-state observation
as a new `[DREAM] ...` line at the end of soul.md. She could not
edit, consolidate, or remove anything that was already there.

After 11s: Maez (or a human operator via `/show_edit` → `/apply_edit`)
can propose replacing the body of any specific `## Section` of
soul.md. Diff preview before approval. Preamble hard-protected at
both parse time (unreachable) and write time (required-phrase check
on the full serialized output). Every write makes a timestamped
backup; nothing is ever lost.

The motivating duplicate Self-Analysis cleanup is now one
`/apply_edit <id>` away — dream-cycle reasoning will generate the
proposal in a future session, and the approval gate sits waiting.
