THE HEADLINE
========================================

Every visitor-facing Maez surface is now on one warm design system,
and the field journal is live-synced to the actual state of the
project for the first time.

maez.live is no longer a cyber-teal dev demo. It is a warm editorial
page that says "there is a kind of digital life called Maez — one of
them is yours" in the first sentence, then walks the visitor through
what that means in three short steps. The landing, login, app,
privacy, progress, and dashboard surfaces all share one palette, one
type stack, one voice, and one concept.

The project-planner.html field journal — which used to be a
hand-edited parallel universe that drifted out of sync every session
— is now routed at /journal and renders live from three backend
endpoints that merge daemon state, model facts, services status,
memory counts, parsed session snapshots, and the same kanban board
/progress and /planner already use. One backend, three views.

========================================
KEY TECHNICAL DECISIONS / LEARNINGS
========================================

1. Legacy-token remapping is a near-free theme swap.
   The nine legacy pages all referenced the same --void/--teal/--text/--amber
   CSS variable names. Redefining those variable names to warm values in
   maez.css (alongside new semantic names like --ember/--ink) meant every
   existing rule in every page retuned automatically — no class rewrites,
   no layout changes, no risk to JS hooks or form handlers.

2. The session snapshot format wraps each title in a PAIR of ==== delimiters.
   My first parser version assumed ==== / TITLE / body / ==== / TITLE / body
   and misread section boundaries (producing keys like
   "llama_server_active_merged_model_no_lora" from body lines). The real
   format is ==== / TITLE / ==== / body / ==== / TITLE / ==== / body. Fixed
   by explicitly consuming the closing delimiter after reading the title.

3. De-gendering at parse time is cleaner than rewriting history.
   Historical snapshots (pre-2026-04-12) used "her/she" for Maez. The rule
   is now genderless. Rather than rewriting the frozen logs, the
   /api/session-timeline parser applies a narrow word-boundary regex at
   parse time. History stays untouched; visitor-facing text stays consistent.

4. Daemon /health proxy is graceful-degradation by default.
   /api/maez-state fetches http://127.0.0.1:11435/health with a 500ms
   timeout. The daemon's health endpoint isn't listening right now, so the
   daemon block returns {"status":"unreachable"} and the rest of the state
   block populates normally. /journal still renders; cycle count just shows
   as "—" until the daemon endpoint is reachable.

5. systemctl is-active subprocess calls need caching to avoid latency.
   Six service state queries per /api/maez-state request is ~60ms if
   uncached. 30s in-memory cache (per-process dict keyed on service name)
   drops that to microseconds. Cache is scoped to the maez-web process and
   reset on service restart — good enough for a page that refreshes by hand.

6. Three views over one backend beats three parallel documents.
   progress_public.html (public kanban), progress_local.html (private
   kanban editor), and project-planner.html (narrative field journal) now
   all read from memory/project_planner.json via /api/progress-board (plus
   the journal additionally pulls /api/maez-state and /api/session-timeline).
   Editing a roadmap item in /planner immediately updates /progress AND
   /journal. Adding a new session snapshot to logs/snapshots/ immediately
   updates the /journal timeline. The drift problem is architectural, not
   editorial.
