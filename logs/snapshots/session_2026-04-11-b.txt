THE CONCEPT IN ONE SENTENCE
========================================

When the owner is AFK for >30 minutes, the daemon occasionally enters
"dream mode": reviews last 40 raw memories, looks for patterns no
individual memory named, writes a reflection, stores it as a
novelty-checked soul-note proposal for manual approval via private

========================================
NEW FILE: core/dream_state.py (~340 lines)
========================================

DreamState class with thread-safe SQLite schema, idle detection,
cadence gate, dream cycle orchestration, Jaccard novelty heuristic,
and proposal lifecycle (pending → applied/rejected).

Public API:
  is_idle(presence_snap, absence_secs) -> bool
    True iff not rohit_present and absence >= IDLE_THRESHOLD_S
  should_run_now(now) -> bool
    True iff >= DREAM_COOLDOWN_S since last dream
  run_dream_cycle(force=False) -> Optional[str]
    Full dream pipeline. Claims cooldown slot at TOP (before work).
  list_pending() -> list[(id, created_iso, insight)]
  get_proposal(id) -> Optional[dict]
  apply_proposal(id) -> (ok, message)
    Writes via action_engine.write_soul_note, marks DB row applied
  reject_proposal(id, reason='manual') -> (ok, message)
    Marks rejected, no soul.md edit

Private:
  _tokenize(text) -> set[str]  (words len>=4, lowercase)
  _is_novel(candidate) -> bool (Jaccard over prior dreams + soul notes)
  _store_proposal(insight) -> int
  _init_schema(), _conn()

Schema:
  CREATE TABLE dream_proposals (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at    REAL NOT NULL,
    insight       TEXT NOT NULL,
    status        TEXT NOT NULL DEFAULT 'pending',
    applied_at    REAL,
    reject_reason TEXT
  );
  CREATE INDEX ix_dream_status ON dream_proposals (status, created_at);

Tuning constants:
  IDLE_THRESHOLD_S = 1800.0     # 30 min AFK required
  DREAM_COOLDOWN_S = 600.0      # 10 min between dreams
  DREAM_MEMORY_WINDOW = 40      # tuned down from 80 after measurement
  MIN_INSIGHT_CHARS = 30        # filter NOTHING + short refusals
  NOVELTY_JACCARD_MAX = 0.4     # max word-set overlap with prior
  NOVELTY_DREAM_LOOKBACK = 20   # prior dreams compared against

THE BACKGROUND THREAD IS CRITICAL.

In the unit test during heavy daemon contention, a dream cycle took
137 seconds. Running inline would block the main reasoning loop for
~4 cycles. Running in a background thread means the main loop keeps
ticking at 30s regardless. The dream sets _last_dream_at at the TOP
of run_dream_cycle (before any work), so the cooldown gate starts
returning False immediately — no risk of spawning a second thread
while the first is still in flight.
