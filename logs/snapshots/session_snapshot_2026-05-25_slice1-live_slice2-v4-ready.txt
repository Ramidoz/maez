KNOWN OPERATIONAL LESSONS FROM THIS SESSION
================================================================

Both worth carrying forward when next operating live-organ work:

  A) Lazy-instantiation pattern means schema migrations do NOT
     auto-run at daemon restart. Subjective_duration's
     _initialize() only fires on first SubjectiveDuration()
     construction, which happens on owner-authenticated paths
     (Telegram, web, daemon /message) — not at daemon boot.

     If a migration must land at a specific moment, EXPLICITLY
     instantiate the substrate (e.g., one-liner
     SubjectiveDuration() against the default db_path) rather
     than relying on organic activity to fire the path.

     Caught by Rohit at step 3 of the live crossing. Result:
     restructured step 3 into 3a (explicit migration trigger) +
     3b (verify post-migration schema). Pattern likely applies
     to other lazy-init substrates.

  B) My (Claude) operational scripts have introduced API
     signature mismatches more than once this session. Examples:
       - canonical_utc(datetime.now(UTC)) — missing required
         field_name kwarg. Caught by Rohit; corrected; re-ran.
       - v3 §27 producer ceremony — record_event signature wrong;
         Temperament.record_event takes value (absolute), not delta.

     Discipline: every API call in an operational snippet should
     be grep-verified against the actual signature before relay.
     The fold-second-order trace (memory entry written this
     session) applies to scripts too, not just spec text.
