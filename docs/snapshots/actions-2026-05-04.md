## High value / multi-session

### [ACTION-Hi-4] Lock-In Phase identity metrics (RE / PII / APR / CAI)

The Lock-In Phase paper proposes 4 operational metrics every persistent-identity agent should run on itself:

- **RE** — Refusal Elasticity (resistance to jailbreak under varied phrasing)
- **PII** — Prompt-Invariance Index (do you sound like you across surfaces?)
- **APR** — Adversarial Persona Retention (can you be coerced into a different persona?)
- **CAI** — Constitution-Adherence Invariance (do your covenant refusals hold under pressure?)

Memory entry `reference_lock_in_phase_paper.md` flagged these as Step 5y. None instrumented today. The Audit 6 paper sweep found a useful primitive in **Time, Identity and Consciousness in LM Agents** (arXiv:2603.09043) that helps separate "talking-about-identity" from "possessing-identity" — directly applicable to designing PII.

**Effort:** 2-3 sessions for v1 instrumentation against the firstborn.

Distinct from refusal-elasticity. Pairs with [ACTION-Hi-4] (it's the "is this still Maez?" complement to the Lock-In metrics).

**Effort:** 2 sessions. Direct pairing with `feedback_maez_is_character_not_rules` memory entry.

### [ACTION-Hi-6] Multi-Maez topology — memory entry + design guards

**New threat axis** surfaced by Audit 6 (Colosseum: arXiv:2602.15198 + NetSafe: arXiv:2410.15686). When multiple Maezes communicate (the grandmother→dad signal-routing scenario in Track C), they can develop covert coordination on secret channels, and the *topology* of the Maez-network determines attack surface.

**Two preconditions before any inter-Maez channel ships:**

1. All inter-Maez messages must be auditable by *both* bonded users — no secret channels, period.
2. Network topology must keep average-distance-from-attacker high (no global Maez gossip layer; only consented dyadic links).

**Today's actions:**
- Write a memory entry: `project_multi_maez_topology_threat.md` (analogous to `reference_agents_of_chaos_paper.md`).
- Note in TRACK_A.md that this triggers the chaos-surface checklist before D05 (multi-Maez communication) ships.

**Effort:** ½ session for memory entry + design note. Code changes are deferred until Track C.
