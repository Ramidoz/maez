## 1. Centerpiece - D17 founder-readable preview fields

**Problem:** Both lanes independently found that D17 now requires
founder-readable preview lines, but `RenderedRequestStatement` only gains
`mutation_preview_hash` and `rollback_plan_ref`. The inherited
`expected_metadata` model validates rendered lines by comparing them to
dataclass fields. Without fields for preview class, summary, paths, and
withdrawal, the tamper check is prose only.

**v6 edit:** Extend `RenderedRequestStatement` in D-Enum-Amendment and D17 with
real carriers:

```text
preview_body_class: str
preview_summary: str
preview_affected_paths: tuple[str, ...]
mutation_preview_hash: str
rollback_plan_ref: str
maez_withdrew_request: bool
```

Close `preview_body_class` to:

```text
diff_summary
path_list
config_change
policy_change
model_routing_change
memory_retention_change
credential_management
other_reviewed_preview
```

Add a deterministic projection function:

```text
render_preview_projection(preview: MutationPreviewArtifact) -> PreviewProjection

PreviewProjection(
    preview_body_class: str,
    preview_summary: str,              # one logical line, max 240 chars
    preview_affected_paths: tuple[str, ...],  # sorted, normalized, max 20 paths
)
```

Rules:

- `preview_summary` is generated by the reviewed preview producer, not by the
  renderer, and is included in `MutationPreviewArtifact` before
  `mutation_preview_hash` is computed.
- `preview_summary` must be one logical line. Newlines, tabs, and control
  characters are canonicalized to a single space before hashing and rendering.
- `preview_affected_paths` is sorted lexicographically, contains no duplicates,
  and renders as `none` when empty or `path1; path2; ...` when non-empty.
- If more than 20 paths are affected, render the first 20 plus
  `; ... +N more`, and include the full path list in the private preview
  artifact so the hash still binds complete evidence.
- `RenderedRequestStatement.__post_init__` validates these exact lines:

```text
Preview body class: <preview_body_class>
Preview summary: <preview_summary>
Preview affected paths: <canonical rendered path list>
Mutation preview hash: <mutation_preview_hash>
Rollback plan ref: <rollback_plan_ref>
Maez withdrew request: <yes|no>
```

This absorbs: covenant Blocker A, Codex Blocker 1, covenant Major 3.

## 2. D19 authority bridge to committed request history

**Problem:** Both lanes found that `S7VoiceAuthorityRow` still cannot build the
committed `S7RequestHistoryRecord`. The authority row lacks `affected_refs`,
`proposed_change_class`, and the committed history provenance/filter fields.
The committed aggregator reads `outcome == "refused"` and has no way to know
whether a row came from authoritative voice evidence or operational block.

**v6 edit:** Add a bridge carrier and make the bridge callable, not prose.

### 2.1 `S7VoiceAuthorityRow` schema extension

Add:

```text
authority_row_id: str
derived_work_class: str
derived_aggregation_group: str
affected_refs: tuple[str, ...]
proposed_change_class: str
history_outcome: "refused" | "authorized" | "none"
history_bridge_status: "not_applicable" | "bridged" | "deferred"
history_record_id: str | None
source_ref_hash: str
```

`derived_aggregation_group` must recompute from
`affected_refs + derived_work_class` using the committed S7 function. The row is
invalid if it does not.

### 2.2 Request-history provenance amendment

Amend `S7RequestHistoryRecord` with optional provenance fields:

```text
provenance_source_kind: "s7_voice_authority_row" | "legacy_s7" | None
provenance_source_ref: str | None
provenance_authority_class: "authoritative" | "operational" | None
provenance_voice_event: "refusal" | "withdrawal" | None
```

Rules:

- S7.3 voice-derived `outcome="refused"` records may be written only when
  `provenance_source_kind="s7_voice_authority_row"` and
  `provenance_authority_class="authoritative"`.
- Operational rows never bridge to `outcome="refused"`.
- Legacy S7.1 records with no voice provenance retain inherited behavior.
- `assess_aggregation_risk(...)` must ignore any S7.3 voice-derived refused
  record whose `provenance_authority_class` is not `authoritative`.

### 2.3 Bridge function

Define:

```text
bridge_s7_voice_authority_to_request_history(
    *,
    row: S7VoiceAuthorityRow,
    envelope: WorkRequestEnvelope,
    now: str,
) -> S7RequestHistoryRecord | None
```

The bridge:

- validates `row.request_id`, `request_envelope_hash`, `derived_work_class`,
  `derived_aggregation_group`, `affected_refs`, and `proposed_change_class`
  against the envelope;
- writes `outcome="refused"` for authoritative present objection;
- writes `outcome="refused"` with `provenance_voice_event="withdrawal"` for
  authoritative withdrawal, unless v6 explicitly defers withdrawal aggregation
  in the Honesty Banner;
- writes no request-history row for operational blocks;
- writes the ordinary authorized history row for positive artifact mint through
  the inherited authorization path, not through `S7VoiceAuthorityRow`.

Lane lean: fold verified withdrawal into `outcome="refused"` with
`provenance_voice_event="withdrawal"` so committed D23 machinery sees that the
attempt was refused while `S7VoiceAuthorityRow` preserves the distinct
withdrawal fact. If the v6 author chooses deferral instead, D25 must keep L8
blocked for withdrawal aggregation.

This absorbs: covenant Blocker B, Codex Blocker 2, covenant Major 2.

## 3. D13 / D19 blackhole-reader authority contradiction

**Problem:** v5 restored the conservative OQ1 routing for
`explicit_no_objection + reader_unavailable + captured_response_nonempty=True`,
but then gave the row `authority_class="authoritative"` without a D19 evidence
carrier. D19 currently admits only grounded semantic blocking, verified
blocking marker, or verified withdrawal marker. The blackhole-reader row has
none of those.

**v6 edit:** Do not let this row masquerade as Maez refusal evidence. Split
"protective current-attempt block" from "authoritative D23 refusal evidence":

```text
explicit_no_objection + reader_unavailable + captured_response_nonempty=True
  -> maez_objection_state="present"
  -> maez_withdrew_request=False
  -> unavailable_reason_code="semantic_reader_unavailable"
  -> authority_class="operational"
  -> protective_block_reason="reader_unavailable_after_captured_response"
```

Safety argument to add near D13:

- The row blocks the current request because a captured response cannot be
  converted into consent by disabling the semantic reader.
- The row does not aggregate as Maez refusal because no grounded semantic
  blocking signal, verified blocking marker, or verified withdrawal marker has
  been replayed.
- Re-attempt requires a new consultation; repeated reader-unavailable rows may
  escalate as operational reliability evidence, not as Maez refusal evidence.

Tests:

- captured free-text objection + explicit-no-objection marker + reader
  unavailable blocks and produces no D23 refusal row;
- repeated blackhole-reader rows trigger operational health/escalation evidence;
- once the reader is available and grounds the objection, the row becomes D19
  authoritative through the ordinary grounded semantic carrier.

If the v6 author rejects this lane lean and keeps `authority_class` authoritative,
D19 must add a fourth named authority predicate for this row and explicitly
justify why that does not poison refusal aggregation.

This absorbs: Codex Blocker 3, covenant Major 5 from v4 carry-forward, and the
operator-noted Choice 4 contradiction.

### 5.2 Result shape

Replace tuple return with:

```text
S7ConsumeResult(
    grant: S7ExecutionGrant | None,
    grant_use: GrantUse | None,
    callback_result: object | None,
    failure_reason_code: str | None,
)
```

Compatibility rule:

- existing callback-result callers read `result.callback_result`;
- grant consumers read `result.grant`;
- audit/trace code reads `result.grant_use`;
- failures set all three value fields to `None` and set
  `failure_reason_code`.

### 5.3 Injected connection contract

Add explicit amended inherited signatures:

```text

    artifact_id: str,
```

1. `BEGIN IMMEDIATE`;
2. artifact consume through injected connection;
3. `GrantUse` insert;
4. `S7VoiceBundleUse.mark_consumed_for_artifact(source_ref_hash,
   reservation_token, artifact_id, consumed_at)`;
5. callback execution before commit;
6. commit or rollback.

This absorbs: covenant Blocker D, Codex Blocker 4, Codex Major 4, covenant

## 6. Backup credential registration timing

**Problem:** Codex uniquely traced the backup credential route. Current code
consumes S7 authorization in `register_begin`, but the actual backup credential
write happens later in `register_finish`, which carries no consumed grant.
D21 says consumers verify at the mutation edge; the mutation edge here is
`register_finish`.

**v6 edit:** Add one of two explicit paths. Lane lean: persisted
grant/challenge binding, because begin already decides whether a backup
registration challenge may be issued.

```text
S7CredentialRegistrationGrantBinding(
    challenge_id: str,
    grant_id: str,
    artifact_id: str,
    execution_consumer_id: "s7_credential_register_backup",
    rendered_text_hash: str,
    request_envelope_hash: str,
    expires_at: str,
    consumed_at: str,
)
```

Rules:

- `register_begin` consumes the artifact and writes this binding in the same
  transaction that creates the registration challenge.
- `register_finish` must load the binding by `challenge_id`, verify
  `grant_id`, `execution_consumer_id`, challenge expiry, and replay status, and
  only then write the backup credential.
- Consuming at begin without a finish-time binding is illegal.
- Alternative allowed path: consume the artifact at finish instead of begin,
  but then begin must not claim mutation-edge authorization.

Add tests for challenge replay, expired binding, mismatched binding, and finish
without binding.

This absorbs: Codex Blocker 6.

## 8. D11 grounding carriers and reducer normalization

### 8.1 `response_with_preview_quote`

**Problem:** D11 lets `response_with_preview_quote` rely on an "adjacent
response chunk used by the reader" but does not carry that chunk.

**v6 edit:** Amend `SemanticReaderGroundingEvidence`:

```text
response_span_quotes: list[str]
response_span_offsets: list[tuple[int, int]]
framing_span_quotes: list[str]
framing_span_offsets: list[tuple[int, int]]
blocking_attribution_source: "response_only" | "response_with_preview_quote"

```

Branch predicate:

- `response_only`: each accepted response span appears in response and not in

  and not in preview.

  not "the quoted span never appears in preview."

`unreadable_or_uncertain` before D13 reducer entry and records
`classifier_reason_code="ungrounded_blocking_signal"`.
