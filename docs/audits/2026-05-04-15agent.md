# Maez — 15-Agent Code Audit & Visual State, 2026-05-04

A 15-agent parallel deep code audit covering every subsystem under `core/`, `daemon/`, `skills/`, and `tests/`. Each agent looked for real gaps: bugs, dead code, missing tests, error-handling holes, race conditions, integration drift. NOT vision/covenant work — that landed yesterday in [`architecture-state-2026-05-04.md`](../snapshots/architecture-state-2026-05-04.md).

This document has three sections:
1. **Audit synthesis** — corrected & ranked findings across the 15 agents
2. **Visual: Maez (architecture state)** — what's built and where it's leaky
3. **Visual: Maez compute (runtime topology)** — what's running, where, with what data flow

- **Dream-cycle race on `_last_departure_time`** not cleared on `just_arrived`
- **Capability-planning loop exception silently waits 1h** before retry
- **PID file false-positive on SIGKILL** — stale file suggests daemon running when it's not
- **`apply_diff()` lacks in-function "user-saw-diff" verification**
- **Scheduler concurrent-run race on proposal rows**
- **Honesty guard post-stream missing audit on terminal fallback** (`telegram_voice.py:3253-3258`)

- **Vague-label dedup logic trap** in `cognition_quality.py:354-357` (works today, fragile to refactor)
- **Public/web `/api/v1/*` endpoints unauthenticated** — safe today only because of 127.0.0.1 binding
- **CORS `*` + no CSRF** — same conditional risk

#### TIER 3 — Test gaps

- **6 public-API modules with no direct test coverage**: `approval_sessions`, `cloud_redactor`, `birth`, `identity_ledger`, `command_decomposer`, `llm_client` shim

- **10 timing-sensitive `time.sleep()` calls** across the suite
- **One real hardcoded path** in `tests/test_model_config.py:125` that breaks contributor clones (the rest are properly `skipTest`-guarded)
- **Reassessment of "wondering_pursuit" flakes** — agent says the tests themselves are clean; the flake is in the daemon's frequency-budget sidecar logic under concurrent message handling, not the tests
