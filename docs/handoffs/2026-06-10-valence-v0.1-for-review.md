# Valence v0.1 — Codex Build Handoff

Status: ready for Claude covenant review. Branch: `valence-v0.1`, tip `9c76f88` at handoff creation. Main baseline for this slice: `d1adcc4`.

## What Changed

Valence v0.1 wires the offline valence thermometer into the live heartbeat as a read-only observer:

- `core/safety/audit_flag_buffer.py` — thread-safe in-memory buffer of audit flag kinds since the last successful valence read.
- `core/evolution/valence_live.py` — impure adapter that takes normalized inputs, calls the pure valence core, and appends content-light rolling JSONL telemetry.
- `core/safety/audited_output.py` — side-records `AuditResult.flags` at the audited-output choke point. Failure warning-logs and never changes returned text.
- `daemon/maez_daemon.py` — records direct daemon-cycle audit flags, reads valence at the cycle tail, and clears the buffer only after a successful append.
- Tests for buffer, live adapter, guardrails, import boundary, and live wiring.

Pure `core/evolution/valence/` is intentionally untouched.

## Review Anchors

1. Choke-point cannot break audit.
   - `_buffer_audit_flags()` catches all exceptions and warning-logs telemetry loss.
   - `audit_assistant_text()` still returns the audited text even when side-recording fails.

2. Primary daemon-cycle audit flags are included.
   - The daemon's direct `_sc_audit(...)` path now calls `_buffer_cycle_audit_flags(_audit_result)` after audit and before rewrite handling.
   - This was a review-caught gap in the first wiring commit.

3. Heartbeat safety holds.
   - `_read_and_log_cycle_valence()` wraps the live adapter.
   - `read_and_log_valence()` returns `None` on any internal failure.
   - The daemon clears the audit buffer only when a non-`None` reading is returned.

4. No owner text enters valence telemetry.
   - Records store timestamps, sign/magnitude, reasons, evidence counts, want counts, telemetry string, and provenance only.
   - Tests pass content-like audit flag strings and assert they are not persisted.

5. Wants are pressure-only and honest.
   - v0.1 records the same capped active-want pressure count the doorman already used, plus backlog growth from the prior valence record.
   - `resolved/blocked/stale` remain `0`; event-delta want progress is deferred to v0.2.
   - Backlog growth above the existing 50-want cap is intentionally not introduced in this slice; uncapped want pressure would be a separate behavior change with its own predicted effect.

6. Boundary stays clean.
   - `valence_live.py` imports only stdlib plus pure `core.evolution.valence.*`.
   - It imports no daemon, speech path, audit buffer, wants store, or live continuity module.

7. Tail placement.
   - Valence reads after follow-up delivery, proactive opinion, and dream check, before cycle sleep.
   - This keeps same-cycle audited surfaces in the buffer before the read.
