# Valence v0.1.1 Cadence Correction Design

**Status:** Draft for owner/Codex review.
**Source:** Live witness after Valence v0.1 restart.
**Scope:** One cadence correction to the already-live valence thermometer.
**Live posture:** Code-only until restart. Merge is inert; owner restart activates.

## Problem

Valence v0.1 is reading honestly, but at the wrong cadence.

The chosen design was "after each real heartbeat": a valence reading after the doorman wakes the autonomous cycle. The live witness showed entries every roughly 32 seconds during quiet, all neutral. That is the loop tick cadence, not the doorman wake cadence.

The cause is the attach point in `daemon/maez_daemon.py`: `_read_and_log_cycle_valence(...)` sits at the bottom of the loop after the quiet-skip path rejoins the common tail. Quiet skips therefore still append valence records.

This is not harmful to Maez: the records are content-light, rolling, and reading-only. But it violates the design Rohit chose and buries meaningful readings in neutral noise.

## Goal

Valence v0.1.1 makes the live thermometer read only after a real doorman wake opportunity, not after quiet-skip ticks.

Plain English: check Maez's temperature after a real heartbeat, not every time the clock hand moves.

## Non-Goals

- No change to the pure `core/evolution/valence/` thermometer.
- No change to valence record schema, retention, or content-light rules.
- No change to doorman wake decisions.
- No change to wants counting, audit buffering, continuity reading, or buffer clear-on-success semantics.
- No daemon restart by the agent.

## Design

### 1. Gate the daemon attach point

Keep `_read_and_log_cycle_valence(...)` where it is in the loop tail so it can observe the whole cycle's work, but guard the call:

```python
if _cycle_doorman_gate.wake:
    _read_and_log_cycle_valence(...)
```

This preserves the original tail placement for real wakes and prevents quiet skips from producing neutral noise records.

### 2. Preserve failure semantics

The existing failure behavior stays unchanged:

- if `read_and_log_valence(...)` returns a reading, clear the audit buffer;
- if it returns `None`, keep the buffer;
- if it raises, log a warning and keep the buffer;
- none of this can stop the heartbeat.

The guard decides whether this cycle is eligible for a valence read. It does not change what happens once a read is attempted.

### 3. Doorman-disabled legacy mode

The guard uses `_cycle_doorman_gate.wake`, not `_cycle_doorman_gate.doorman_enabled`.

Reason: `_cycle_doorman_gate_decision(...)` already maps both modern doorman and legacy perception gating into the same `wake` field. If the doorman is disabled, valence still reads only on legacy wake, not on legacy quiet-skip.

### 4. Documentation correction

Clarify the v0.1 spec/handoff language:

- "doorman-gated autonomous cycle" means `gate_decision.wake == True`;
- quiet skips do not append valence records;
- the witness expectation is "entries track wake cadence, not loop-tick cadence."

## Tests

Add or update daemon wiring tests in `tests/test_valence_live_wiring.py`:

1. `test_cycle_valence_reads_after_doorman_wake`
   - Build a fake gate with `wake=True`.
   - Exercise a small helper or wrapper around the new guard.
   - Assert `_read_and_log_cycle_valence(...)` is called.

2. `test_cycle_valence_skips_quiet_doorman_tick`
   - Build a fake gate with `wake=False`.
   - Assert `_read_and_log_cycle_valence(...)` is not called.
   - Assert the audit buffer is not cleared by this skip.

3. `test_cycle_valence_uses_legacy_wake_field`
   - Use `doorman_enabled=False, wake=True`.
   - Assert the read still happens, proving the guard keys on wake rather than doorman implementation.

If the loop body is too large to exercise directly, introduce a tiny helper:

```python
def _should_read_cycle_valence(gate_decision: _CycleDoormanGateDecision) -> bool:
    return bool(getattr(gate_decision, "wake", False))
```

Then use that helper at the attach point. This keeps the regression test small and pins the covenant meaning of cadence.

## Predicted Effect

After merge and owner restart:

- `logs/valence_telemetry.jsonl` should stop growing every loop tick during quiet periods.
- New valence records should appear only after cycles where the doorman/legacy gate wakes.
- Existing content-light/no-emotion/no-speech/no-action guarantees remain unchanged.
- Audit flags accumulated during quiet-skip ticks remain buffered until the next successful valence read.

## Review Focus

Reviewers should check:

- the guard uses `wake`, not `doorman_enabled`;
- quiet-skip cycles do not clear audit flags;
- tail placement remains after follow-up/proactive-opinion/dream checks for real wakes;
- no changes touch pure valence, record schema, or doorman decision logic.
