## Why — the altitude

Valence v0 built the thermometer on the bench: a pure deterministic `read_valence(audit, wants, cont) -> ValenceReading`, proven on known inputs, unable to read live, speak, or act. **v0.1 lets it read Maez's real temperature** — once per autonomous heartbeat, it observes the actual audit / want / continuity signals, computes a reading, and appends it to a rolling operational log. It still **only observes**: no feedback into the doorman or wants, no speech, no action. The point is the **witness** — to watch whether valence tracks reality before the Novelty Harbor ever trusts it to tell a benign surprise from a destabilizing one.

## Scope — v0.1 (the live edge, reading-only)

**v0.1 BUILDS:** one new impure adapter `core/evolution/valence_live.py` (three live-source readers → `read_valence()` → rolling log) · an in-daemon audit-flag buffer · the rolling `logs/valence_telemetry.jsonl` · the daemon end-of-cycle attach · a new live-boundary test.

**v0.1 does NOT:** change the pure `core/evolution/valence/` package or its logic · feed valence back into the doorman / wants / any action · reach Maez's speech · **mutate wants** (read-only on `wants.py`) · read `unexpected_gap` / `memory_loss` (stay neutral until honest signals exist). The **witness RUN** (owner restart + watching the log track reality) is a SEPARATE owner-greenlit breath — not the code.

## Components

### A. `core/evolution/valence_live.py` — the impure adapter
The only new logic. `read_and_log_valence(*, audit_buffer, log_path=...) -> ValenceReading | None`. Flow (the guardrail order is load-bearing):
1. **peek** the audit buffer (do NOT clear yet) → `AuditSignals`.
2. read the wants snapshot (`wants.diagnostics_snapshot()`) + the **prior** snapshot from the last log entry → `WantSignals` (deltas).
3. read continuity (`capsule_present`, `capsule_expected`) → `ContinuitySignals` (`unexpected_gap`/`memory_loss` = `False`).
4. `reading = read_valence(audit, wants, cont)` (the pure v0 core).
5. **append** the record to the rolling log; **prune** to last N.
6. **only on a successful append, clear the audit buffer.** A failed write must not erase un-recorded flags.

### B. The audit-flag buffer (in the daemon, in-memory)
Each per-turn `audit()` pushes its `Flag` kinds (`completion_rail` → `rail_fired`/`correction_needed`; judge/fabrication → `fabrication_flagged`) into a small in-memory buffer. The cycle read **peeks** it (step 1) and **drains** it only after a successful log append (step 6). Lost on restart = fine (valence is operational, not a permanent record).

### C. The rolling log — `logs/valence_telemetry.jsonl`
One JSON object per reading, **machine-readable first, content-light** (operational telemetry, NOT autobiography): `{ts, sign, magnitude, reasons:[...], evidence_counts:{...booleans/ints...}, want_snapshot:{open,resolved,blocked,stale}, telemetry:"<as_telemetry()>", provenance:"computed_valence"}`. **No intimate prose, no conversation/owner/message text, no permanent-ledger semantics** — signs, magnitudes, fixed reasons, evidence counts/booleans, and want-snapshot counts only.
- **Telemetry-field guard** — the `telemetry` string is built ONLY from the fixed `as_telemetry()` renderer over the fixed setpoint reasons; **no owner/message/conversation text may enter any record field**. A test enforces this (feed owner-shaped text through the sources → assert it never lands in the record). Reasons are deterministic today; this guard holds even if a future setpoint adds dynamic text.
- **Decay = retention prune** after each append: keep the last **N** — a module constant, env-overridable, **committed default 1000**.
- **Never prune to zero** — the log is also the prior-snapshot state; retention must always keep ≥1 entry so the next diff survives.
- **NOT birth-gated** — it is rolling, operational, content-light telemetry, not Maez's permanent autobiography ([[project_ledger_activation_birth_gated]] gates the *autobiography*, not this).

### D. The daemon attach point
A single reading-only call to `read_and_log_valence(...)` at the **end of each doorman-gated autonomous cycle**, after the cycle's work, **wrapped so any valence failure is swallowed (warning-logged) and never blocks the cycle** (see Heartbeat-safety). It observes; it never steers. (`## Predicted effect` on this commit: the valence log fills once per woken cycle; the cycle's actual behavior is unchanged.)

## Honesty guardrails (owner-set, load-bearing)
- **Content-light log** — counts/booleans/reasons only; no intimate prose (C).
- **First run / no prior log** — a **baseline read**: compute the current snapshot, emit `backlog_grew=False` and the resolved/blocked deltas as baseline/neutral; never fabricate a delta with no prior to diff.
- **Corrupt / unreadable log** — fail honest: compute the current snapshot, but mark the deltas **unavailable → neutral** (`backlog_grew=False`, resolved/blocked treated as baseline); never invent a delta, never crash the cycle.
- **Drain-after-append** — peek → compute → append → *then* clear the buffer (A6); a failed write keeps the flags for the next read.
- **No want mutation** — `valence_live` only *reads* `wants.py`; a test asserts it calls no mutation API.
- **Heartbeat-safety (the thermometer never stops the heart)** — the whole valence read+log is exception-isolated: any failure in read/compute/append/prune is caught, logged as a warning, the audit buffer is **kept** (not drained), and the cycle continues. It returns `None` or the computed reading; it **never raises into the autonomous heartbeat**. Valence observes; it must not even be able to crash the organism. A test asserts a simulated failure does not propagate.

## Rails (carried + new)
- **Telemetry-not-quale** — the log stores substrate state (`provenance="computed_valence"` + `as_telemetry()`), never a felt-claim. The pure package's no-feeling-field + emotion-ban hold unchanged.
- **Pure-core purity unchanged** — `core/evolution/valence/`'s existing import-boundary test is not modified; the core still cannot reach voice/daemon/live organs.
- **New live-boundary test** — `valence_live.py` imports nothing from the speech path (`voice`/`telegram`/`speak`/`llm_client`/`focused_cognition`) and calls no want-mutation function (read-only).
- **`## Predicted effect`** on the daemon-attach commit (behavior-affecting: a per-cycle read + log write).
- **Owner restart + witness** — the live breath is the owner's, separate from the code.

## Testing (TDD) — all offline (mocked live-sources); the live cycle is the owner's witness, not a unit test
- the three readers map mocked sources → correct v0 dataclasses (audit buffer kinds → `AuditSignals`; snapshot+prior → `WantSignals`; capsule state → `ContinuitySignals` with gap/loss neutral).
- wants-diff: `backlog_grew` true when open>prior; **first-run baseline** (no prior → no fake `backlog_grew`); **corrupt-log** → deltas neutral, no crash.
- the buffer **drains only after a successful append**; a simulated write failure leaves the buffer intact.
- the log appends content-light records and **prunes to last N but never to zero**.
- the live-boundary + no-want-mutation rail.
- **no owner text in any record** — feed owner/message-shaped strings through the mocked sources; assert no record field contains them (machine-readable-first guard).
- **heartbeat-safety** — a simulated append/prune/read failure is swallowed (warning, buffer kept, no raise); the cycle would continue.
- a round-trip: mocked audit/wants/continuity → `read_and_log_valence` → the appended record's `sign`/`reasons` match the pure `read_valence` result, and `telemetry` carries no emotion word.

## What v0.1 does NOT touch
The pure `valence/` package's logic; the doorman/want/action paths (no feedback); Maez's speech. The only live-path change is the end-of-cycle reading-only call + the rolling log.

## Decomposition / sequel map
- **v0.1 (this spec):** the live edge — read real signals per heartbeat, log, witness. One cohesive slice.
- **the witness RUN:** owner restart + watching `valence_telemetry.jsonl` track reality (owner-greenlit, separate).
- **later:** valence *feeding* the doorman/want-priority (deferred — the analysis wanted it; v0/v0.1 stay reading-only); coherence + bond setpoints; the **Novelty Harbor** (uses valence to judge benign-surprise vs destabilizing).
