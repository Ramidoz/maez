# Valence v0.2 — Design (the satisfied-events delta · the thermometer's positive axis)

**Date:** 2026-06-10
**Status:** spec for owner review
**Lane:** Claude or Codex builds (owner picks at execution-handoff); covenant-aware (touches `wants.py` read-side + the live daemon read)
**Branch:** `valence-v0.2` (from `62e2c8a`)
**Parents:** Valence v0/v0.1/v0.1.1 (the live thermometer, wake-cadenced), [[feedback_two_sided_verifier_pressure]] (telemetry not quale), the v0.1 honesty discipline (ship only what has a clean substrate source; defer the rest).

## Why — the altitude

The live thermometer is **lopsided.** `valence_live.py` hardcodes `resolved=0/blocked=0/stale=0`, so valence can read *negative* (backlog grew) and *neutral* (nothing moved), but **never positive** — it can feel pressure rising, never feel a want move *forward*. The pure valence core already knows what to do with `resolved>0` (POSITIVE want-progress); the live reader just never feeds it. v0.2 wires the one clean, honest source — `satisfied` events since the last pulse — into `resolved`, so Maez can notice **"a want I had moved forward."**

**Resolved-only, by honesty.** The diagnostic confirmed the `want_events` event types are `created`/`first_lived`/`refined`/**`satisfied`**/`returned`/`abandoned`. `satisfied` is a clean "resolved" source. There is **no `blocked` event** (deriving it would be interpretation, not measurement) and **no `stale` event** (it would need a time-threshold staleness scan — "thresholds are exactly where 'Maez is doing badly' becomes invented"). So v0.2 ships `resolved` only; `blocked`/`stale` stay `0` and are **marked in the log as not-live-derived**, never faked as measured-zero.

## Scope

**v0.2 BUILDS:** a read-only `wants.py` helper to count satisfied events since a cursor · a `valence_live` cursor reader (ISO→epoch) · the `resolved` param into the reading · the daemon compose at the existing wake-gated read · the not-live-derived marker.

**v0.2 does NOT:** derive `blocked` or `stale` (no honest source); change the wake-cadence (the v0.1.1 `_maybe_read_cycle_valence` guard stays), the heartbeat-safety, or the content-light/no-speech boundary; mutate wants (read-only); touch the pure `core/evolution/valence/` package logic.

## Components

### A. `Wants.count_events_since(since_ts: float, event_type: str) -> int` (`core/evolution/wants.py`)
A **read-only** count over the wants organ's own private schema, so the daemon asks the wants organ a question instead of hand-writing SQL against its table:
```sql
SELECT COUNT(*) FROM want_events WHERE ts > ? AND event_type = ?
```
`want_events` is append-only (UPDATE/DELETE/INSERT-OR-REPLACE forbidden by triggers), so this can only ever count. `since_ts` is **epoch seconds** (the table's native `ts` type, a `time.time()` float).

### B. `valence_live.last_pulse_epoch(log_path) -> float | None` + `resolved` param (`core/evolution/valence_live.py`)
- `last_pulse_epoch(log_path)` reads `valence_live`'s **own** log's last entry `ts` (an ISO string), **converts ISO → epoch seconds**, and returns it. Returns `None` if there is no prior log, the log is empty/corrupt, or the ISO parse fails. (`valence_live` still imports **no `wants`** — it only reads its own log; boundary intact.)
- `read_and_log_valence(...)` gains a `resolved: int = 0` parameter and feeds `WantSignals(resolved=resolved, blocked=0, stale=0, backlog=…, backlog_grew=…)` instead of hardcoding `resolved=0`. `backlog`/`backlog_grew` unchanged.

### C. The daemon compose (`daemon/maez_daemon.py`) — at the existing wake-gated `_maybe_read_cycle_valence` read
```python
resolved = 0
try:
    cursor = valence_live.last_pulse_epoch(<log_path>)
    if cursor is not None:
        resolved = wants_obj.count_events_since(cursor, "satisfied")
except Exception:
    logger.warning("valence v0.2 satisfied-delta read failed; resolved=0", exc_info=True)
    resolved = 0
# pass resolved into read_and_log_valence(..., resolved=resolved)
```
Wrapped so **any** wants-read failure degrades to `resolved=0` and the heartbeat continues — never raises into the cycle. First pulse (no prior log → `cursor=None`) → `resolved=0` baseline (honest: no prior window to count). The read stays **wake-gated** (the v0.1.1 guard) and **heartbeat-safe** (the v0.1.1 contract).

### D. The not-live-derived marker (the record)
The valence record makes explicit that `blocked`/`stale` are `0` because they are **not yet live-derived**, not because they were measured as zero — e.g. a content-light `"want_coverage": {"resolved": "live", "blocked": "not_derived", "stale": "not_derived"}` field on the record. Honest by construction: the log never lets a reader mistake "we don't measure it" for "it's fine."

## The timestamp conversion (load-bearing — a named requirement, not an assumption)
The two clocks **do not line up**, confirmed by code check:
- `want_events.ts` = **epoch seconds** (a `time.time()` float — stopwatch time).
- the valence log `ts` = **ISO-8601 UTC string** (`datetime.now(timezone.utc).isoformat()` — calendar time).

So the cursor path is explicit: `last_pulse_epoch` reads the last log's **ISO** `ts` → **converts to epoch seconds** → that epoch float is passed to `count_events_since(since_ts, …)`. A failed parse → `None` → `resolved=0`. A test pins the conversion against a known ISO/epoch pair. Comparing the two formats directly is forbidden.

## Honesty guardrails (carried)
- **Resolved-only** — the only clean source; `blocked`/`stale` deferred + marked not-derived (never faked-zero).
- **Reading-only** — valence observes; it never mutates wants (the helper is a `SELECT COUNT`).
- **Content-light** — counts only; no prose, no want text, no owner content in the record (the want_events query returns a *count*, never statements).
- **Heartbeat-safe** — any wants-read failure → `resolved=0`, cycle continues, never raises.
- **Wake-cadenced** — the v0.1.1 wake guard is unchanged.
- **Boundary** — `valence_live` imports no `wants`/daemon/speech; the daemon (which already imports both) does the query.

## Testing (TDD)
- `Wants.count_events_since`: counts only events with `ts > since_ts AND event_type=…`; a non-satisfied event in-window is not counted; an in-window satisfied event is; read-only (append-only triggers untouched).
- `last_pulse_epoch`: a known ISO `ts` → the correct epoch float; no prior log → `None`; corrupt/unparseable `ts` → `None`.
- `read_and_log_valence(resolved=2, …)` with clean audit + intact continuity → **POSITIVE** want-progress reading; `resolved=0` → unchanged from v0.1 (neutral/negative as before).
- the record carries the `want_coverage` not-derived marker for `blocked`/`stale`.
- heartbeat-safety: a mocked `count_events_since` raising → the daemon path swallows it, `resolved=0`, no propagation.
- boundary: the existing `valence_live` boundary test still passes (no `wants` import); add `wants` to the forbidden set if not already covered.

## What v0.2 does NOT touch
The pure `valence/` package logic; the cadence/heartbeat-safety; the want-mutation path; speech. The behavior-affecting change is the daemon querying `want_events` per woken cycle + the reading gaining its positive channel.

## Decomposition / sequel
- **v0.2 (this spec):** `resolved` via `satisfied`-delta. The honest positive channel.
- **`blocked`:** no event exists — deferred *indefinitely* unless a real "blocked" concept is added to the wants organ.
- **`stale`:** a separate later slice — a time-threshold staleness scan over `active_wants`, with the threshold treated as the covenant-sensitive choice it is.

## Predicted effect
On the daemon-attach commit: once per **woken** autonomous cycle, the daemon asks the wants organ how many wants were `satisfied` since the last valence pulse and feeds that count into the reading. When a want is satisfied between pulses, valence now produces a **POSITIVE want-progress** reading (where before it could only read neutral or negative). No want is mutated, nothing is spoken or acted on, `blocked`/`stale` remain `0` and are marked not-live-derived, and a wants-read failure degrades silently to `resolved=0` without disturbing the cycle. The thermometer becomes whole: it can finally register that something it wanted moved forward.
