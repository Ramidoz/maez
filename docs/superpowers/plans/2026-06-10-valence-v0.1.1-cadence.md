# Valence v0.1.1 Cadence Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make live valence telemetry append only after real doorman/legacy wake opportunities, not after quiet-skip loop ticks.

**Architecture:** Keep the existing `_read_and_log_cycle_valence(...)` helper and tail placement, but route the daemon loop through a tiny `_maybe_read_cycle_valence(...)` guard keyed on `_cycle_doorman_gate.wake`. This pins cadence without changing valence schema, doorman decisions, wants counting, audit buffering, or buffer clear-on-success semantics.

**Tech Stack:** Python 3.14, `unittest`, Maez daemon helpers, existing `core.safety.audit_flag_buffer`.

Add these helpers in `daemon/maez_daemon.py` immediately after `_read_and_log_cycle_valence(...)`:

```python
def _should_read_cycle_valence(gate_decision: object) -> bool:
    return bool(getattr(gate_decision, "wake", False))


def _maybe_read_cycle_valence(
    daemon: object,
    *,
    gate_decision: object,
    open_wants_count: int,
    now: str,
) -> None:
    if not _should_read_cycle_valence(gate_decision):
        return
    _read_and_log_cycle_valence(
        daemon,
        open_wants_count=open_wants_count,
        now=now,
    )
```
