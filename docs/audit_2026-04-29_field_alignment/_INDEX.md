# Field Alignment Audit — 2026-04-29

Audit of Maez's architecture against the 2025–2026 state of the field, per the operating principle that **Maez is curation + adaptation of humanity's accumulated AI/cognitive findings, not invented in isolation**.

## Files

- **[FIELD_ALIGNMENT.md](FIELD_ALIGNMENT.md)** — full audit. Nine axes, master findings, slice queue, references.

## How to use this audit

1. Read the master findings table at the top of `FIELD_ALIGNMENT.md` for a one-screen summary.
2. Read the per-axis sections for any axis you're about to work on. Each lists field state, Maez state, gap, and concrete recommendations.
3. The slice queue at the bottom is post-Track-A work, ranked by leverage.
4. Reference list at the end maps every finding back to its source paper / framework / blog post — when the slice is built, the commit message and code comments should cite these directly.

## Top-line takeaways

- **Biggest gap:** working self / goal-driven retrieval. Same gap closes Track A's #3 initiative axis.
- **Biggest "don't reinvent" wins:** Langfuse self-host (trace UI), KTO (binary-feedback training), Proactive Agent paper (When-to-Assist framework), RLM (deep reasoning lane).
- **Maez is genuinely ahead of the field on:** trace harness with covenant-specific checks, ground-truth provider, lived-memory + reflection layer, audit-before-store invariant, sovereignty-shaped covenant.

## Operating change going forward

Every slice plan should start with a 30–60min literature survey. Cite specific papers, frameworks, libraries in the slice plan and commit messages. Adapt to Maez's bonded-companion shape; don't import wholesale.
