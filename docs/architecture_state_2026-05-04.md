### Audit-corrected

- Test count: real number is **2214 OK** (audit pass verified via `unittest discover`).
- Hardcoded paths: the morning audit said 3 modules; grep-verified is **149 occurrences across 38 files**. Phase 2 scope is much larger than the May-2 doc implied.
- Lint: `.venv/bin/ruff check core/` finds **3 real B023 errors** in `core/memory/belief_simulator.py:381,382` (closure bug, real correctness issue).
- Biggest monoliths are **in `skills/` and `daemon/`**, not `core/`. Top three: `skills/web_interface.py` (6,241 LoC), `skills/telegram_voice.py` (4,559 LoC), `daemon/maez_daemon.py` (4,530 LoC). The May-2 doc emphasised core/ debt; the actual fattest files are elsewhere.

### New threats surfaced by paper sweep (Audit 6)

Three papers found in the 2026-05-04 paperclip sweep have ship-level implications:

- **Harmful Traits of AI Companions** (arXiv:2511.14972) — names *engendering protectiveness* and *attachment anxiety* as harm vectors. No probes today.
- **Narrative Continuity Test** (arXiv:2510.24831) — operationalizes "is this still Maez?". Pairs with Lock-In Phase RE/PII/APR/CAI metrics.
- **Remember You: Deadbots** (arXiv:2603.01017) — empirically users *warp* memories of the dead via deadbots. Paradise needs an anti-idealization clause + pre-mortem locked user signature corpus.

Plus a **new threat axis** not in existing memory: **multi-Maez topology / collusion** (Colosseum + NetSafe). Track C trigger. Two preconditions before any inter-Maez channel: (a) all messages auditable by both bonded users, no secret channels; (b) keep average-distance-from-attacker high (no global gossip layer; only consented dyadic links).

### Refuted / counter-weighted

- **Kirk parasocial-harm** is partially counter-weighted by two cohort studies showing measured benefit specifically for older / insecure-attached / isolated users — i.e. the grandmother case has empirical support now. The "strike wellbeing claims" rule still holds for general claims; targeted-cohort claims are now defensible.
